**Фаза 4 начата.** Владелец передал первый настоящий документ — выписку по

догадкой: порядок дат, разделители сумм, повторяемость шапки, наличие итогов
только по документу. Главная находка осмотра — сегментатор не собирал таблицу этого
документа — разобрана и устранена: у всех страниц выписки объявлен поворот на
90 градусов, а разбор PDF его не учитывал, и строкой оказывалась колонка.
Поворот теперь учитывается, версия координатной системы поднята до второй,
порог склейки строк измерен по впадине в разрывах и объявлен подгонкой под
первое семейство. Дата стоит первой ячейкой в 99,7 процента строк, строк с
несколькими датами не осталось, 3 318 строк-проводок имеют ровно по семь
ячеек. Следом прочитана шапка — восемь колонок, положение каждого заголовка
одинаково на всех 218 страницах, — и выведено измерением правило границы
операции: первая строка начинается в самой левой полосе, куда ни одно
продолжение не заходит. Правило объявляет оснастка, исполняет ядро. Собрано
3 318 операций, учёт сходится: 12 390 строк разошлись по записям и по
названным поимённо строкам вне записей. По измеренному написана оснастка
первого семейства, и документ прошёл конвейер с нею: **3 318 записей разобраны
по полям без единого неистолкованного поля, баланс сошёлся** — входящий остаток
плюс поступления минус списания равно исходящему, — сошлись и обороты по дебету
и по кредиту. Ни одна запись не отклонена; все в review, потому что шесть
слагаемых формулы допуска из одиннадцати остаются неизвестными. Устойчивость
разбора проверена без новых файлов: документ разрезан на десять частей и
прогнан постранично — обе разрезки дали те же 3 318 записей, учёт сошёлся
всюду, неистолкованных полей ноль. На свойствах документа целиком держится
только проверка баланса, и по существу дела: остатки напечатаны на первой
странице. Из шести неизвестных слагаемых три закрываются работой по коду,
два требуют документов с разметкой, одно — решения о стороннем
распознавателе. Список нужных документов передан владельцу отдельным файлом. Затем закрыты два
слагаемых из шести: собрано **происхождение значения** — по каждому полю адрес
области источника, сырьё, движок, версия, правило преобразования и итог, и на

оригинала; и **порядок с повторами** — измерено, что номера документов

## Канал обмена

Обмен с внешним миром идёт через GitHub, а не через приложение Google Диска.
Станок кладёт файл в `exchange/outbox`, `exchange/send.py` тут же отправляет
ящик, GitHub Actions публикует. Действий человека в цепочке нет ни одного.

Читается ящик через сайт. Сайт кеширует страницы до десяти минут, и это принято
как данность: безвредным кеш делает правило имён — **имя файла в ящике никогда
не переиспользуется**, по каждому адресу лежит одно неизменное содержимое.
Исправление отчёта кладётся новым файлом с суффиксом `-2`, `-3`. Правило держит
не обещание, а станок: попытка переписать закреплённое имя останавливает
публикацию. Подробности и хеши — в [README ящика](README.md) и `opis.json`.

Сама опись меняться обязана, и потому у каждого выпуска ящика есть **своя
неизменная опись** — `vypuski/opis-NNN.html`. По такому адресу список не
изменится никогда.

Номер свежего выпуска и ссылка на его неизменную опись стоят **на пульте**:
<https://lordrubano.github.io/stanok-pult/>. Пульт пересобирается при каждом
коммите, и спрашивать номер у человека больше не нужно.

Эта сводка — единственное исключение: она обновляется на месте, и читать её надо
с поправкой на возможную несвежесть.

Что наружу не уходит никогда: настоящие документы, журналы запусков, корпус.
Проверено приманками и на бумаге (`tests/test_outbox_guard.py`, `tests/test_send.py`),
и вживую: подложенные копии из `corpus/` и `runs/` вместе с книгой Excel
остановили публикацию, наружу не ушло ничего.
